# Wizard surface

Target: apps/web/src/App.tsx. Mode: Operate. Authority: issue #2 and the implementation plan approved for PR #3. The product interview and visual direction are complete; preserve their composition.

Process experts turn their description and situation into a checked model through types, facts, actions, refinement, situation, and plan. Developers can reveal construction. Desktop-first, keyboard accessible, 5–40 sentences and plans of 3–60 steps. Storage defaults to configurable runs/. Login, setup, workflow compilation, and MoltNet branding are excluded.

## Direction contract

THESIS: The expert's words are a galley and model elements are keyed proof marks. The signature interaction is selecting either a sentence or its mark and seeing the other highlighted.

OWN-WORLD: White stock and dark ink with blue selection/actions, green passed/met/added states, amber review questions/removals, and red corrections. Hairline rules, Literata prose, Public Sans controls, numbered lines and compact passed stamps. Labels supplement color; exact tokens live in DESIGN.md. Flat sheets with no decorative imagery.

STORY: Describe a process, inspect its extracted meaning, correct misunderstandings, pass each gate, and test the resulting plan against changing facts.

FIRST VIEWPORT: A slim masthead with the run name and rack access; a routing slip; a numbered description with model annotations alongside when space permits. Plan expands to a horizontal progression and state walkthrough. Description starts hidden in Plan; description and construction are independently revealed with Show/Hide buttons. Reference panels reflow to the available sheet width. The current gate sits at the bottom of the working sheet.

FORM: Galley Proof, the user-selected direction recorded in issue #2 and the prior direction-round payload (model-pick). The approved plan supplies the fixed composition; continue directly with its functional interface. No new direction tournament.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Review language

Use plain-language “Correction required” and “Check with the author” findings. Questions and missing source references use collapsible disclosures inside the corresponding action; errors start expanded. Literal Qy symbols and strike-through marks are not required. Never invent a replacement or source citation to simulate proofreading. Exact wording and optional technical details preserve the distinction between a model error, an advisory question, and missing evidence.
